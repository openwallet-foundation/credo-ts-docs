This page covers what is specific to mdoc (ISO/IEC 18013-5, `mso_mdoc`) in each OpenID4VC step: the credential configuration, the issuer certificate, signing in the credential mapper, trust, requesting data elements with DCQL, and reading the result. [Issuing credentials](./issuer.mdx), [Receiving and presenting](./holder.mdx) and [Verifying credentials](./verifier.mdx) explain the flow itself, and [mdoc](../../credential-formats/mdoc.mdx) explains the format. To request mdocs from a website with ISO 18013-7 Annex C, see [Digital Credentials API (ISO 18013-7)](../mdoc/dc-api.mdx).

## Configure the credential

Add an `mso_mdoc` entry to the `credentialConfigurationsSupported` of the issuer:

```ts showLineNumbers title="issuer.ts" openid4vc-mdoc.ts section-1
```

- `doctype` is the document type, such as `org.iso.18013.5.1.mDL` for a mobile driving licence. Credo checks that every mdoc the mapper returns has this doctype.
- An mdoc is always bound to a key of the holder, never to a DID. `cose_key` (or `jwk`) in `cryptographic_binding_methods_supported` tells the wallet so.
- In `credential_metadata.claims`, the `path` of a data element is its namespace and element identifier.
- Add a `scope` if you offer the credential through the [authorization code flow](./authorization.mdx).

## Create the issuer certificate

mdocs are signed with an X.509 certificate, the document signer certificate:

```ts showLineNumbers title="issuer.ts" openid4vc-mdoc.ts section-3
```

- The subject must have a country (`countryName`). Verification fails without it, and checks that `issuing_country` in the mdoc matches it (and `issuing_jurisdiction` the state, if present).
- In production, the document signer certificate is issued by your issuing authority CA (IACA), and verifiers trust the IACA certificate. Pass the chain as an array, leaf first, to include it in the mdoc.
- The signing certificate needs the KMS key id of its key, which `agent.x509.createCertificate` sets.

[X.509 certificates](../../dids-and-trust/x509.mdx) explains creating certificates and certificate chains.

## Sign the credential

The mapper returns the mdoc sign options, one entry for each holder key:

```ts showLineNumbers title="issuer.ts" openid4vc-mdoc.ts section-2
```

- `docType` must be the `doctype` of the configuration, and `holderKey` is the key from `holderBinding`.
- `validityInfo` needs `validUntil`. `signed` and `validFrom` default to now, and `expectedUpdate` is optional.
- `namespaces` maps each namespace to its data elements. Use `DateOnly` for elements of type `full-date`, such as `birth_date`. Every data element can be disclosed on its own.
- Optional: `keyAuthorizations` for data elements the wallet may sign itself (device signed), and `statusInfo` for revocation with a [status list](../../credential-formats/status-lists.mdx).

## Trust the issuer

The holder verifies the mdoc when it receives it, and the verifier verifies it again in the presentation. Both need the issuer certificate or its IACA root:

```ts showLineNumbers title="trust.ts" openid4vc-mdoc.ts section-4
```

Without a trusted certificate, verification fails. To decide per verification, for example from a list of IACAs, use `getTrustedIssuersForVerification` in the agent config. See [Trusted issuers](../../dids-and-trust/trust.mdx).

## Receive and store

The binding resolver must return keys (`method: 'jwk'`):

```ts showLineNumbers title="holder.ts" openid4vc-mdoc.ts section-5
```

`requestCredentials` doesn't store anything. The `MdocRecord` has one instance per mdoc the issuer returned. `record.firstCredential.issuerSignedNamespaces` has the data elements per namespace.

## Request data elements with DCQL

The verifier asks for an mdoc by doctype and lists the data elements it needs:

```ts showLineNumbers title="verifier.ts" openid4vc-mdoc.ts section-6
```

- `format` is `mso_mdoc` and `meta.doctype_value` the doctype.
- Each claim `path` is a namespace and a data element identifier. `intent_to_retain` tells the wallet whether you store the element.
- The wallet discloses only the requested data elements.
- With OpenID4VP 1.0 (the default `version`), both `direct_post` and `direct_post.jwt` work. With drafts 21 and 24, mdoc requires `direct_post.jwt`.

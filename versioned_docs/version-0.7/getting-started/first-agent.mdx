This page builds the smallest complete agent: it stores data and keys in an Askar SQLite database, creates a `did:key`, resolves it and shuts down. You need the packages from [Installation](./installation.mdx).

The `Agent` constructor takes three options:

- `dependencies` are the platform implementations of the file system, `fetch`, WebSocket and events. Import `agentDependencies` from `@credo-ts/node` or `@credo-ts/react-native`.
- `modules` adds features to the agent. The `AskarModule` registers Askar as the storage and as a [key management](../agent-setup/key-management.mdx) backend. An agent needs a storage module: without one, `new Agent()` throws `Missing required dependency: 'StorageService'`.
- `config` holds agent-wide settings, such as the logger. See [Agent configuration](../agent-setup/index.mdx).

`store.id` names the database and `store.key` encrypts it. On Node.js the database is created at `~/.afj/data/wallet/<id>/sqlite.db`. See [Askar](../agent-setup/storage/askar.mdx) for the options, PostgreSQL, and how to choose the key.

## Modules and their APIs

The key you register a module under is the name of its API: `agent.modules.askar` for the module above. `didcomm` and `openid4vc` are also available as `agent.didcomm` and `agent.openid4vc` when you register them under those keys. Default modules, such as DIDs, key management and SD-JWT VC, are always registered and have their APIs at the top level, for example `agent.dids` and `agent.kms`.

TypeScript infers these APIs from the `modules` you pass, so using a module you didn't register is a type error. [Agent configuration](../agent-setup/index.mdx) lists the default modules and shows how to type an agent you pass around.

## Initialize

```ts showLineNumbers first-agent.ts section-2
```

`initialize()` opens the Askar store, or creates it on the first run, and checks that the storage is up to date for this version of Credo. Call it once, before you use the agent.

## Create and resolve a DID

```ts showLineNumbers first-agent.ts section-3
```

`agent.dids.create()` creates an Ed25519 key in Askar, stores a DID record that links the DID to the key, and returns the `did:key`. `resolveDidDocument()` resolves the DID to its DID document, and throws if that fails. See [DIDs](../dids-and-trust/index.mdx) for other DID methods.

## Shut down

```ts showLineNumbers first-agent.ts section-4
```

`shutdown()` stops the modules and closes the store. Call it before your process exits or your app is closed.

```text
INFO: Creating agent with config { ... }

{
  "@context": [
    "https://www.w3.org/ns/did/v1",
    ...
  ],
  "id": "did:key:z6Mkg...",
  "verificationMethod": [ ... ],
  ...
}
```

Run it again and the agent opens the existing store and adds a second DID.

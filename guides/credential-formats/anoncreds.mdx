title: AnonCreds
description: Set up AnonCreds in Credo with a registry, register schemas, credential definitions and revocation registries, and manage link secrets and stored credentials.
---

[AnonCreds](https://hyperledger.github.io/anoncreds-spec/) credentials are signed with CL signatures, which let a holder present zero-knowledge proofs: reveal only some attributes and prove a predicate such as "age is at least 18" without the value. Verifiers can't link presentations through the signature. Holders bind credentials to a link secret instead of a key. Issuers publish schemas, credential definitions and revocation data on an AnonCreds registry, usually a ledger. This page covers setup and the issuer and holder APIs. Credo exchanges AnonCreds credentials only over DIDComm: see [AnonCreds with DIDComm](../protocols/didcomm/anoncreds.mdx).

Each registry handles the identifiers of one DID method, and Credo uses the first registry that matches an identifier. A registry also needs the module of its network, which provides the DID resolver:

| Registry | Import from | Identifiers | Network setup |
| --- | --- | --- | --- |
| `IndyVdrAnonCredsRegistry` | `@credo-ts/indy-vdr` | `did:indy`, and unqualified Indy identifiers for resolving | [Indy VDR](../dids-and-trust/indy-vdr.mdx) |
| `CheqdAnonCredsRegistry` | `@credo-ts/cheqd/anoncreds` | `did:cheqd` | [cheqd](../dids-and-trust/cheqd.mdx) |
| `HederaAnonCredsRegistry` | `@credo-ts/hedera/anoncreds` | `did:hedera` | [Hedera](../dids-and-trust/hedera.mdx) |
| `WebVhAnonCredsRegistry` | `@credo-ts/webvh/anoncreds` | `did:webvh` | [did:webvh](../dids-and-trust/webvh.mdx) |

The cheqd, Hedera and did:webvh packages have `@credo-ts/anoncreds` as an optional peer dependency, so install it yourself. Hedera also needs `@hiero-did-sdk/anoncreds`. To register objects on Indy, the issuer needs a `did:indy`.

```

- `issuerId` is a DID on the registry that the issuer created or imported in its agent.
- `options` depend on the registry. Indy VDR needs `endorserMode` and `endorserDid`, and you can type them with `registerSchema<IndyVdrRegisterSchemaOptions>`. cheqd needs none.
- The register methods don't throw when registration fails. Check `state`: `finished`, `failed` (with `reason`), `wait`, or `action` (for example when an external Indy endorser has to sign).

A credential definition binds a schema to an issuer and holds the issuer's public keys. You issue against a credential definition.

```

:::

Credo keeps the private keys in the issuer's wallet. Without that wallet you can no longer issue with this credential definition. Use `tag` to create several credential definitions for one schema. Set `supportRevocation: true` if you want to revoke credentials later: you can't add revocation afterwards.

## Link secrets and stored credentials

A link secret is the holder's secret that all its AnonCreds credentials are bound to. By default (`autoCreateLinkSecret: true`) Credo creates one on the first credential request. The first link secret becomes the default. You can also create one yourself, and `getLinkSecretIds` lists them:

:::holder

```ts showLineNumbers title="holder.ts" anoncreds-setup.ts section-4
```

:::

The holder stores AnonCreds credentials as W3C VCDM 1.1 credentials (`W3cCredentialRecord`) with a `DataIntegrityProof` using the `anoncreds-2023` cryptosuite. `getCredentials` filters them by credential definition, schema or issuer and returns the attributes and identifiers, and `getCredential(id)` returns one. `agent.w3cCredentials` lists the same records, but its `verifyCredential` rejects AnonCreds proofs.

## Verifying

A verifier checks AnonCreds presentations during the [Present Proof](../protocols/didcomm/present-proof.mdx) exchange. It resolves the schemas, credential definitions and status lists from the registries. Which issuers you accept is part of the proof request, through `restrictions`. The agent's [trusted issuers](../dids-and-trust/trust.mdx) configuration doesn't apply to AnonCreds.

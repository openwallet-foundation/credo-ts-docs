---
title: Credential formats
description: The credential formats Credo supports, how they compare, and which protocols carry them.
---

A credential format defines what a credential looks like, how the issuer signs it and how the holder presents it. Formats are separate from exchange protocols: you can sign, store, present and verify a credential with the agent APIs alone, and most formats work over more than one protocol. The pages in this section cover each format on its own. For the flows, see [Protocols](../protocols/index.mdx).

## Compare the formats

| Format | Selective disclosure | Holder binding | Unlinkable presentations | Issuer identified by | Standard | Used in |
| --- | --- | --- | --- | --- | --- | --- |
| [SD-JWT VC](./sd-jwt-vc.mdx) | Yes, per claim | Key (`cnf`) | No | DID or X.509 certificate | IETF | EUDI Wallet (PID and attestations) |
| [mdoc](./mdoc.mdx) | Yes, per data element | Device key | No | X.509 certificate | ISO/IEC 18013-5 | Mobile driving licence, EUDI Wallet (PID) |
| [W3C VC](./w3c-vc.mdx) | Only data model 2.0 as SD-JWT | DID of the subject, or key (`cnf`) in 2.0 | No | DID | W3C | Open Badges, EBSI |
| [AnonCreds](./anoncreds.mdx) | Yes, per attribute, with predicates such as "over 18" | Link secret | Yes | DID and credential definition on a ledger | Hyperledger AnonCreds | Aries and Indy based ecosystems |

For SD-JWT VC, mdoc and W3C VCs, every presentation of a credential carries the same issuer signature, so verifiers that compare notes can link presentations of it. Issuers avoid that with batch issuance: the holder gets several copies, each bound to its own key, and presents each copy once. AnonCreds presentations are zero-knowledge proofs and don't have this problem.

## Protocols and APIs

| Format | Exchanged over | Agent API | Record |
| --- | --- | --- | --- |
| SD-JWT VC | OpenID4VC, Digital Credentials API | `agent.sdJwtVc` | `SdJwtVcRecord` |
| mdoc | OpenID4VC, Digital Credentials API | `agent.mdoc` | `MdocRecord` |
| W3C VC 1.1 | OpenID4VC, DIDComm | `agent.w3cCredentials` | `W3cCredentialRecord` |
| W3C VC 2.0 | OpenID4VC, DIDComm (depends on how it's secured) | `agent.w3cV2Credentials` | `W3cV2CredentialRecord` |
| AnonCreds | DIDComm | `agent.modules.anoncreds` (the key you register it under) | `W3cCredentialRecord` |

All formats except AnonCreds are part of `@credo-ts/core`, and their modules are registered on every agent. AnonCreds needs `@credo-ts/anoncreds` and a ledger. For the protocol versions and the full matrix, see [Supported standards](../supported-standards.mdx).

## Which one should I use?

- Follow your ecosystem first. The EUDI Wallet uses SD-JWT VC and mdoc, a mobile driving licence is an mdoc, Open Badges are W3C VCs, and Aries networks use AnonCreds.
- For a new OpenID4VC deployment without such a requirement, start with SD-JWT VC. It has selective disclosure and works with both DIDs and X.509 certificates.
- If you use DIDComm and need unlinkable presentations or predicates, use AnonCreds.

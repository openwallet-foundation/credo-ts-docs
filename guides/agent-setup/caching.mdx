Credo caches data that is slow to fetch: resolved DID documents, AnonCreds objects from ledgers and revocation lists of X.509 certificates. A cache is always registered, and you only replace it in two cases: when you use [multi-tenancy](./multi-tenancy.mdx), and when several instances of the agent run side by side.

## Which should I use?

Keep the default for a single agent without tenants, such as a mobile wallet: nothing to configure, and entries survive a restart. Use `InMemoryLruCache` when the agent has tenants, because the default throws as soon as a tenant uses it. Use `RedisCache` when several instances of the agent run behind a load balancer, so they share one cache. With the default, instances overwrite each other's cache record in the shared storage, and with `InMemoryLruCache` each instance fetches and caches everything on its own.

| Cache | Package | Tenants | Several processes share it | Survives a restart |
| --- | --- | --- | --- | --- |
| `SingleContextStorageLruCache` (default) | `@credo-ts/core` | No | No | Yes |
| `InMemoryLruCache` | `@credo-ts/core` | Yes | No | No |
| `RedisCache` | `@credo-ts/redis-cache` | Yes | Yes | Yes |

The default keeps up to 500 entries in memory and saves them as a record in the agent's storage. When a tenant uses it, it throws `SingleContextStorageLruCache can not be used with multiple agent context instances`.


`InMemoryLruCache` removes the least recently used entries when it reaches `limit`. The limit applies to all agent contexts together.

| `CacheModule` option | Description |
| --- | --- |
| `cache` | The cache to use. Required. |
| `defaultExpiryInSeconds` | Expiry for entries set without one. `RedisCache` uses it. Default `60`. |
| `useCachedStorageService` | Also caches DIDComm connection, mediation and mediator routing records, to save storage reads on busy DIDComm agents such as mediators. Default `false`. With several instances, only turn it on with a cache they share, such as Redis. |

## What is cached

| Data | Cached for | Scope |
| --- | --- | --- |
| Resolved DID documents, for methods whose resolver allows caching (`did:web`, `did:webvh`, `did:cheqd`, `did:indy`, `did:sov`, `did:hedera`). `did:key`, `did:jwk` and `did:peer` aren't cached. | 5 minutes, change it with `cacheDurationInSeconds` when resolving | Global for methods in `DidsModule({ publicDidMethods })`, otherwise per agent context |
| AnonCreds schemas, credential definitions, revocation registry definitions and status lists | 5 minutes | Global |
| Summaries of X.509 certificate revocation lists | Until the list's next update | Global |
| Indy VDR: which ledger a DID is on | Until evicted | Global |
| DIDComm connection, mediation and mediator routing records, with `useCachedStorageService: true` | Until evicted | Per agent context |

Global entries are public data that all tenants share. `publicDidMethods` defaults to `web`, `indy`, `sov`, `cheqd`, `hedera` and `webvh`.
